# 1. 模块清单（扩展侧）

## 1.1 UI（Vue SPA）

职责：

- 以卡片列表展示所有"检测到媒体"的网页（按 Tab 维度），并在卡片上直接交互
  - 每张卡展示：标题/站点/播放状态/进度（可选）
  - 每张卡提供：播放/暂停、上一首/下一首（按需）
- 展示连接状态：桌面连接（Native Messaging）是否可用
- 提供"置顶/设为主控 Tab"（可选）：影响桌面命令默认路由目标

边界：

- UI 不直接做媒体控制与桌面通信细节；只发命令给 Hub Core，并订阅状态。

## 1.2 Hub Core（MV3 Service Worker）

职责：

- 维护全局状态：`byTabId`、`activeTabId`、`lastFocusedTabId`、桌面连接状态
- 路由命令：
  - UI → Content Script（媒体控制）
  - Desktop → Content Script（媒体控制）
  - Content Script → UI（状态同步）
- 管理桌面会话：
  - SW 启动时自动 `connectNative`
  - 接收 `GetMediaList` 命令：有状态立即回复；无状态时广播 `queryState` 给所有 tab，600ms 后回复
  - 状态变化时 debounce 100ms 推送 `evt/MediaList`
- 管理 Tab 生命周期：
  - `tabs.onRemoved` 清理状态
  - `tabs.onActivated` 更新 `lastFocusedTabId`

边界：

- Hub Core 不直接操作 DOM；所有媒体操作必须下发到 Content Script。

## 1.3 Content Script（每个 Tab）

职责：

- 探测该页面是否存在可控媒体
- 执行媒体动作：
  - play/pause
  - prev/next（优先走 Media Session，必要时 fallback）
  - seek（可选）
- 上报状态变化：
  - playing/position/metadata（尽量从 Media Session/DOM 获取）

边界：

- 不持久化全局状态；只向 Hub Core 上报本 tab 状态。

## 1.4 Desktop Bridge（Native Messaging 通道）

职责：

- 扩展侧：由 Hub Core 维护连接；封装为 `desktopBridge` 模块
- 桌面侧：Native Messaging Host 负责与桌面核心业务交互（托盘/快捷键等）

边界：

- 桌面侧仅负责"发命令、收状态、回执"，不介入网页媒体执行细节。

# 2. 模块清单（桌面侧）

## 2.1 Native Messaging Proxy (Go/Rust - 新增)

职责：
- 生命期跟随扩展的 Service Worker。由 Chrome 拉起，负责 `stdin/stdout` 的读取与写入。
- 启动后连接本地预定义的 Named Pipe (例如 `\\.\pipe\MediaControlHubPipe`)。
- 执行透明的双向 JSON 透传。
- 遇到 `stdin` EOF 时立即安全退出，防止僵尸进程。

边界：
- 绝对无状态，没有任何媒体控制或配置逻辑。

## 2.2 Desktop Core (HxMonitor Qt App)

职责：
- 独立运行的 GUI 应用程序（托盘/快捷键/状态窗）。
- 作为 Named Pipe Server，允许多个 Proxy 客户端连入。
- 将桌面输入（快捷键/托盘）转换为 `cmd`，并**广播(Broadcast)**给所有已连接的 Proxy。
- 接收并解析各 Proxy 丢过来的 `evt/MediaList`，更新聚合媒体列表 UI。
- 实现单实例运行（防止用户多开）。

边界：
- 不再直接读取 `stdin`。不负责被浏览器拉起的生命周期。

- stdin/stdout framing：读写 JSON 消息（二进制模式）
- 使用 `QTimer` 10ms 轮询 + `PeekNamedPipe` 读取 stdin（替代不可靠的 `QSocketNotifier`）
- 检测 NM 模式：`stdinIsPipe()` 判断是否由浏览器启动，NM 模式跳过 UAC 提权
- 将桌面输入（快捷键/托盘）转换为 `cmd` 发给扩展
- 接收扩展事件（`evt/MediaList`），更新媒体列表 UI
- 始终写入 `HxMonitor_debug.log`（与 exe 同目录）

边界：

- 不直接做网页媒体控制；扩展才是主控执行者。

# 3. 实际目录结构

```
extension/
  ui/
    App.vue              # 主页面：卡片列表 + 连接状态
  sw/
    index.ts             # SW 入口：注入依赖、注册监听器、自动连接
    hub/
      store.ts           # 全局状态管理 + notifyUI/notifyDesktop
      router.ts          # 命令路由：处理 Desktop/UI/Content 消息
    desktop/
      bridge.ts          # Native Messaging 连接封装
  content/
    index.ts             # Content Script 入口
    detect/
      media.ts           # 媒体探测、状态上报、stop() 清理
    actions/
      control.ts         # 媒体控制执行（play/pause/next/prev/pip）
  shared/
    protocol/index.ts    # NM 消息类型定义（Envelope/CmdName/EvtName）
    types/index.ts       # 共享类型（MediaState/HubState）
native-host/
  com.hxmonitor.proxy.json     # NM Proxy 清单 (指向 e2c_proxy.exe)
  install.bat                  # 注册到 Windows 注册表
  uninstall.bat                # 卸载
```

# 4. 接口约定（模块间）

- UI <-> Hub Core：runtime messaging（request/response + push updates）
- Hub Core <-> Content Script：runtime messaging（tab 定向）
- Hub Core <-> Proxy：native messaging（长连接 stdin/stdout）
- Proxy <-> Desktop：Named Pipe (IPC 进程间通信)
