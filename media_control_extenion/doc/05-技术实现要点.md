# 1. 扩展形态与关键约束

本项目为 MV3 扩展：

- **Hub Core 在 Service Worker 中运行**：SW 可能被浏览器回收；UI 打开时通过 `getState` 重新同步状态。
- **媒体控制必须在网页上下文执行**：通过 Content Script 控制 DOM / Media Session API。
- **桌面双向通信通过 Native Messaging**：Hub Core 维护长连接，对接着系统的 Headless Proxy 层。

# 2. 媒体控制实现（Content Script）

## 2.1 探测策略

- 每 2s 轮询一次 DOM，`querySelectorAll("video, audio")`
- 优先选正在播放的元素（`!paused`），否则取第一个
- 每次找到新元素时重新绑定事件监听器；旧监听器通过闭包引用精确解绑（防内存泄漏）

## 2.2 状态上报

上报时机：
- `play` / `pause` 事件：即时上报（带 `isInteraction: true`）
- `timeupdate` 事件：节流为每秒最多 1 次
- SW 广播 `queryState` 时：立即上报当前状态

元数据优先级：`MediaSession` > 站点适配（Bilibili）> `og:image` > `video.poster` > 页面 title / favicon

## 2.3 动作执行

| 命令 | 实现方式 |
|---|---|
| `PlayPause` | `el.play()` / `el.pause()` |
| `Next` | `navigator.mediaSession` nexttrack → fallback `currentTime += 10` |
| `Prev` | `currentTime -= 10` |
| `TogglePip` | `requestPictureInPicture()` / `exitPictureInPicture()` |

# 3. Hub Core 实现（Service Worker）

## 3.1 状态结构

```typescript
HubState {
  connection: { connected: boolean, lastError?: string }
  media:      { activeTabId: number|null, byTabId: Record<number, MediaState> }
  ui:         { pinnedTabId: number|null, lastFocusedTabId?: number }
}
```

`activeTabId` 计算优先级：`lastFocusedTabId` 有媒体 → `playing=true` 最近活跃 → `lastActiveAt` 最大

## 3.2 SW 重启恢复

SW 被回收后内存状态清空。恢复流程：
1. UI 打开 → 发 `getState` → SW 广播 `queryState` 给所有 tab
2. Desktop 发 `GetMediaList` → SW 状态为空时广播 `queryState`，600ms 后回复

## 3.3 命令路由

```
来源            目标 tabId 选择
UI 卡片操作  →  卡片携带的 tabId（精确定位）
Desktop 命令 →  activeTabId（自动计算）
```

命令发送失败（tab 已关闭）时自动 `removeTab` 清理状态。

## 3.4 Desktop 通知（notifyDesktop）

状态变化（updateMediaState / removeTab / setConnectionState）后 debounce 100ms 发送 `evt/MediaList`。

# 4. 独立 Proxy 层设计保障跨环境兼容

## 4.1 Native Messaging 的硬限制解决
MV3 规范中，浏览器每次执行 `connectNative()` 都会**硬性地创建出一个全新的子进程**。
如果目标是 GUI 程序，将导致电脑上弹出一大堆托盘和图形界面。
本项目通过引入 `Proxy.exe` 作为前置缓冲，它是个纯粹的数据泵（Data Pump），从而彻底将“浏览器宿主生命周期”与“桌面 GUI 程序生命周期”剥离开来。

## 4.2 Proxy 的生命周期
**生**：由扩展 Service Worker 以 Native Messaging 形式激活。
**存活**：与本地统一的 HxMonitor（Named Pipe Server）保持 IPC 连接，双向透传 JSON。
**死**：浏览器关闭或 SW 被回收时，会向 `stdin` 发送 EOF。Proxy 读取到 EOF，即刻执行自我销毁 `exit(0)`。

# 5. Desktop Host 实现 (HxMonitor Qt)

## 5.1 剥离 Stdio 依赖
使用 `QLocalServer` 取代以往的 `PeekNamedPipe` 轮询读写方案，完全阻断了 HxMonitor 与浏览器的直接纠缠。
这从根本上利用了 Qt 的 `readyRead` 事件循环机制，大大降低了桌面端的 CPU 开销。

## 5.2 多 Proxy 的广播架构
桌面程序从以前的一对一变成了 **1 对 N**。
所以当用户点击“按键”发命令时，不再是定点单发，而是向 `QList<QLocalSocket*>` 所有活跃客户端进行 **广播 (Broadcast)**。
**防重放（Idempotent）**处理交由浏览器的 `Hub Core` 来负责（即不是它所属的 Tab 就不执行）。

## 5.3 职责边界

- **桌面侧负责**：接收各路 Proxy 转发的 `evt/MediaList` 展示聚合列表、发送 `cmd` 广播命令
- **桌面侧不负责**：被浏览器拉起、读取 stdin、控制网页媒体执行细节
